The 4 Functional User Portals

The application segments workflows into 4 role-gated user portals, each with customized views, capabilities, and data access barriers.

Super Admin

Full Governance
  • Institution-wide KPI metrics (ratings, total counts)
  • Department lifecycle: create, toggle active, reset passwords
  • Selective data purge (students, faculty, sessions, or all)
  • Full audit log inspection across all departments

Department HOD

Operations Head
  • Session creator: Sem & Sec verification gates
  • Live tracking: see missing/pending/done student roster
  • Automated batch email dispatch with credentials
  • SAGAR Autonomous Copilot with voice navigation
  • AES-256 encrypted internal communications with faculty

Faculty Member

Analytics & Profile
  • Scorecards: Overall score, response volume, 4-tier distribution
  • Radar analysis: question-by-question comparative scores
  • One-click downloadable multi-sheet Excel (.xlsx) reports
  • Generative AI corporate headshot photo enhancement

Student

Anonymous Evaluator
  • Passwordless login using USN + active Session ID
  • Step-by-step evaluation wizard for each assigned course
  • Dynamic question categories with 1-5 rating scale
  • Zero USN association: feedback cannot be traced to identity
  • Single-submission enforcement via idempotency token

Core System Workflows & Sequences

End-to-end execution paths illustrating how frontend components, backend services, and database transactions collaborate.

1. Anonymous Feedback Submission & Concurrency Guard

How student evaluations are submitted atomically with zero trace of student identity.

1

Idempotency Token Acquisition

When the student reaches the feedback page, the client requests GET /feedback/token. The server issues a cryptographically random UUID using crypto.randomUUID().

2

Token Registry Locking

Upon submission to POST /submit-feedback, an atomic Knex database transaction begins (db.transaction()). The server attempts to insert the idempotency token into global_used_tokens. If a duplicate request occurs simultaneously, MySQL throws ER_DUP_ENTRY and aborts immediately.

3

Pessimistic Student Row Locking

The student record in global_students is selected with a pessimistic lock: .where({ usn, session_id }).forUpdate(). If feedback_given === 'done', the transaction rolls back.

4

De-Identified Feedback Persistence

The feedback ratings are looped and inserted into global_student_feedback containing only faculty_id, course_id, question_id, rating, and session_id. The student's USN is omitted entirely.

5

Completion Flagging & Transaction Commit

The student's entry in global_students is updated to feedback_given: 'done'. The transaction commits. Data integrity is guaranteed even under concurrent network spikes.

2. Faculty Generative AI Profile Transformation

How faculty profile photos are processed via Cloudinary generative AI and cached with zero latency.

1

In-Memory Upload

The user selects a portrait photo. Multer intercepts the file in memory (multer.memoryStorage()) without writing unencrypted temporary files to the disk.

2

Cloudinary Upload with Temporary Tag

The buffer is streamed to Cloudinary in folder faculty_profiles tagged as temp_upload. An AI transformation URL is synthesized applying face restoration (gen_restore) and generative background replacement (gen_background_replace:prompt_corporate_headshot...).

3

Zero-Latency Pre-Warming

Before the user clicks "Preview AI", the React client secretly executes: new Image().src = res.data.aiUrl. The browser downloads and caches the neural-rendered image in the background, making the UI transition instantaneous.

4

Permanent Persistence & Orphan Cleanup

When the user clicks "Save", the temporary tag is removed. The faculty record global_faculty.profile_picture_url is updated. The previous image public ID is queried and destroyed via cloudinary.uploader.destroy() to conserve cloud quota.

3. Automated Student Notification Email Pipeline

How students receive secure login credentials and session IDs via responsive HTML emails.

1

Target Query Extraction

The HOD triggers POST /session/notify/:session_id. The server queries all students enrolled in the target semester and section with non-null email addresses.

2

Dynamic HTML Rendering with Inline Assets

Nodemailer compiles a modern HTML email with inline CID attachment (cid:collegelogo) to ensure the college emblem loads without third-party image blocking. The student's specific USN and Session ID are embedded into styled credential cards.

3

Concurrent Settled Dispatch

Emails are dispatched via Promise.allSettled() through the Gmail SMTP transporter. Failed individual transmissions are counted and reported back to the HOD without breaking the batch process.

SAGAR: Autonomous Administrative AI Copilot

SAGAR is an AI agent running directly in Node.js on top of the Groq SDK (model openai/gpt-oss-120b). It operates via a real-time WebSocket connection to execute administrative workflows autonomously.

Swarm Router Architecture

Before executing tool calls, an ultra-fast Router classification prompt evaluates user intent and categorizes it into one of four states: NAVIGATION, ANALYTICS, ACTION, or GENERAL. Only relevant function calling tools are passed to the completion stream, optimizing token consumption and execution latency.

prepare_create_session { sem: integer, section: string } Validates student and faculty enrollment in the database, then sends an interactive confirmation card to the user.

// 1. Router Agent Intent Classification
const routerResponse = await groq.chat.completions.create({
  messages: [
    { role: "system", content: "Classify user intent into ONE exact word: NAVIGATION, ANALYTICS, ACTION, or GENERAL." },
    { role: "user", content: data.message }
  ],
  model: "openai/gpt-oss-120b",
  max_tokens: 10,
  temperature: 0.1
});
const intent = routerResponse.choices[0]?.message?.content?.trim().toUpperCase() || "GENERAL";

// 2. Sliding Window Memory Guard (Prevents Token Context Overflow)
let payloadMessages = messages;
if (messages.length > 15) {
  payloadMessages = [messages[0], messages[1], ...messages.slice(-13)];
}

// 3. Tool Filtering by Classified Intent
let activeTools = [];
if (intent.includes("NAV")) activeTools = copilotTools.filter(t => ['navigate_to', 'open_faculty_profile'].includes(t.function.name));
else if (intent.includes("ANAL")) activeTools = copilotTools.filter(t => ['analyze_faculty_feedback', 'get_top_performing_faculty', 'generate_chart'].includes(t.function.name));
else if (intent.includes("ACT")) activeTools = copilotTools.filter(t => ['prepare_create_session', 'prepare_approve_faculty', 'prepare_add_course'].includes(t.function.name));

Security, Privacy & Cryptography

Multi-layered security protocols engineered into every tier of data ingestion, transmission, and persistent storage.

AES-256-CBC Encrypted Notes

systemController.js Communication Security

Internal performance remarks and notes exchanged between HODs and faculty are encrypted using AES-256-CBC before writing to the database. The encryption key is derived using crypto.scryptSync() with a 16-byte initialization vector. Plaintext never touches persistent storage.

Encryption Implementation 
const ENCRYPTION_KEY = crypto.scryptSync(env.SESSION_SECRET, 'salt', 32);
const IV_LENGTH = 16;

function encrypt(text) {
  let iv = crypto.randomBytes(IV_LENGTH);
  let cipher = crypto.createCipheriv('aes-256-cbc', Buffer.from(ENCRYPTION_KEY), iv);
  let encrypted = cipher.update(text);
  encrypted = Buffer.concat([encrypted, cipher.final()]);
  return iv.toString('hex') + ':' + encrypted.toString('hex');
}

Horizontal Access Prevention

authMiddleware.js Multi-Tenant Isolation

To prevent Insecure Direct Object Reference (IDOR) attacks, the middleware inspects URL parameters, query parameters, and request body attributes. If an authenticated user from Department A attempts to query Department B, the request is immediately terminated with HTTP 403 Forbidden.

Horizontal Barrier Implementation 
const isDepartment = (req, res, next) => {
  if (!req.session || req.session.role !== 'department') {
    return res.status(401).json({ error: "Unauthorized: Department access required" });
  }
  const targetDept = req.params.dept_id || req.query.dept || req.body.dept_id;
  if (targetDept && req.session.dept_id !== targetDept) {
    return res.status(403).json({ error: "Forbidden: Cross-department access strictly prohibited" });
  }
  next();
};
